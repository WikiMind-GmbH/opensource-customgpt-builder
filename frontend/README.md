# Frontend

The frontend is a React and TypeScript application. It communicates with the
FastAPI backend through a generated TypeScript client.

## Run

Start the development stack from the repository root:

```sh
make up
```

For VS Code debugging, use the `React debugger` launch configuration.

## Prerequisites

- Install the prerequisites documented in the repository root README.
- Use the Docker workflow for running and managing the application.
- Optionally run `npm ci` inside `frontend/` if VS Code needs host-side
  `node_modules` for IntelliSense.

## npm package management

The project commits both `package.json` and `package-lock.json`. Docker images
use `npm ci` to install exactly the locked dependency tree, while dependency
changes are made explicitly through Make targets.

Common commands:

```sh
make check-frontend-deps
make update-frontend-deps
make add-frontend-dep PACKAGE=date-fns
make add-frontend-dev-dep-exact PACKAGE=@hey-api/openapi-ts@0.99.0
make audit-frontend-deps
make verify-frontend
make clean-restart-frontend
```

See [NPM_PACKAGE_MANAGEMENT.md](./NPM_PACKAGE_MANAGEMENT.md) for the complete
workflow, including compatible updates, major upgrades, exact pins, lockfile
behavior, and the Docker `node_modules` volume.

## Generated API client

The client is generated by `@hey-api/openapi-ts` from the OpenAPI document
served by FastAPI.

When backend routes or schemas change, run:

```sh
make generate-client-ts-frontend
```

The target:

1. Starts the development containers if necessary.
2. Waits for the backend health check.
3. Reads `http://backend:5173/openapi.json` from inside Docker.
4. Generates the client into `frontend/src/client`.

Generator settings are defined in
[`openapi-ts.config.ts`](./openapi-ts.config.ts). The generated client uses
Axios, groups inputs by HTTP location, and throws on unsuccessful responses.

Do not edit files under `src/client` manually. They are replaced whenever the
client is regenerated.

The deprecated generator remains available only for comparison or rollback
work:

```sh
make generate-client-ts-frontend-deprecated
```

It writes an incompatible legacy client into the same output directory. Run
`make generate-client-ts-frontend` afterward to restore the current client.

## API base URL

The generated client is configured at application startup in `src/main.tsx`:

```ts
client.setConfig({ baseURL: "https://localhost/api" });
```

This setting is outside the generated directory and therefore survives client
regeneration.

## Calling backend endpoints

Generated SDK functions and types are exported from `src/client/index.ts`.

For example:

```ts
import { createCustomGpt } from "../client";
import type { CommandResult, CustomGptToCreate } from "../client";

const body: CustomGptToCreate = {
  custom_gpt_name: "Example",
  custom_gpt_description: "An example custom GPT",
  custom_gpt_instructions: "Answer concisely.",
};

const { data: result }: { data: CommandResult } =
  await createCustomGpt({ body });
```

Hey API generates standalone SDK functions rather than service classes.
Request values are grouped by their HTTP location:

```ts
await createCustomGpt({ body });
await getCustomGptInfos({
  query: { custom_gpt_id: id },
});
```

With the Axios client, the backend response payload is available through the
response's `data` property.

## File uploads

OpenAPI 3.1 binary upload fields are generated as `Blob | File`:

```ts
export type BodyUploadFiles = {
  uploadFile: Blob | File;
  gpt_ids: Array<string>;
};
```

The generated upload function can therefore be called directly:

```ts
const { data: result }: { data: CommandResult } = await uploadFiles({
  body: {
    uploadFile: file,
    gpt_ids: selectedGptIds,
  },
});
```

## Verification

Run the frontend typecheck and production build together:

```sh
make verify-frontend
```

After dependency changes, also run:

```sh
make audit-frontend-deps
make clean-restart-frontend
```
